# 修正設計書：出退勤アプリの打刻漏れ対策とエクセル出力の改修

- 作成: 2026-11-08 Claude
- 対象: タイムカードアプリ（GitHub `sbsrd3mission/timecard`、`timecard.html` と `gas_backup.gs`）
- 状態: 初版（レビュー前）
- 調べた資料: アプリのコード（最新コミット c6edd5b）、スプレッドシート「タイムカードバックアップ」（2026-11-08 時点の写し。シート138枚・EditLog 625行・Confirmations 29行）、「年次有給休暇管理簿2026」、10月分の出力ファイル（2回目）

## 1. 依頼の内容

1. 打刻したのに翌日反映されていない・手入力の修正が多い。動きの悪さや壊れやすい所を調べて直す。打刻が遅い、人が重なると待たされる、という声もある。
2. エクセル出力について
   1. 月1回の出力が1回目で揃わない（11/7 調査済み）
   2. スタッフが確認ボタンを押しているのに全員「本人確認：未」になる
   3. 草野さん・高橋さんと新しい人（西尾さんなど）でシートの見た目が違う。草野さんの形にそろえる
   4. 残有給日数・次回発生日が「出力した日」の値になり、対象月の値にならない（10月分は11月に作るので手で直している）

作らないもの（chihiro判断）: AIでのシフト突き合わせ、暗証番号ロック。

## 2. 調べてわかったこと

### 2.1 打刻の反映漏れ（依頼1）

**数字で見た現状**: 10月の勤怠181件のうち49件（27%）に【本人修正済】が付いている。修正履歴（EditLog）を見ると、9件は「退勤のときに出勤も同じ時刻で押され、あとで出勤時刻を直している」形（例: 東さん 10/3 出勤19:20・退勤19:20 → 出勤10:54 に修正。東さんは10月に5回）。つまり**朝の出勤がスプレッドシートに一度も届いていない**。また10/2には高橋さん10/1分の出勤09:40が空欄で上書きされて消えている記録がある。

打刻は基本的に**店舗のPCとタブレット（共用端末）**で行っている（chihiro 2026-11-08）。共用端末が2台あり、出勤と退勤を別の端末で押すことがあるため、「片方の端末が相手の打刻をまだ知らない」状態が起きやすい。さらに共用端末では次の事情が重なる。
- 打刻のたびに「ローカル更新後15秒は同期しない」保護が掛かり直す。出勤が続く時間帯はその端末の同期と再送が止まり続ける（再送は同期の中でしか動かないため）。
- タブレットは画面が消える・スリープすると、送信や再送が止まる。

原因は次の5つ（Aの「スマホを閉じる」は、共用端末では「タブレットのスリープ・送信中の通信切れ」に読み替え）。

| # | 原因 | どこ | 起きること |
|---|---|---|---|
| A | **送信の取りこぼし**。打刻は「送りっぱなし（no-cors）」で、届いたかを確認できない。さらに送信直後にスマホの画面を閉じたり別アプリに切り替えると、送信そのものが止まることがある（keepalive 指定なし）。それでも画面には「記録しました！」と出る | `sendToGAS` | 本人は押したつもり、クラウドには無い |
| B | **再送が遅く、しかも捨てられる**。未送信分の再送は「その端末で次にアプリを開いて、全件取得に成功したとき」だけ。次に開くのが翌日だと、その間に別端末で退勤が押されて新しい時刻の行ができており、サーバーは「古いデータ」として再送分を捨てる。端末側も「クラウドの方が新しい」と見て未送信リストから消す | `retrySendPending`・`writeRecord` の新旧判定 | 朝の出勤が永久に消える |
| C | **1日分の行をまるごと上書き**。打刻のたびに1日分の全項目（出勤・退勤・賄い・備考…）を送り、サーバーはそのまま行を書き換える。退勤を押した端末が出勤をまだ受け取っていないと、「出勤＝空」で上書きする | `handlePunch`・`writeRecord` | 出勤時刻が消える（10/1高橋さんの例） |
| D | **サーバーの負荷**。開いている全端末が3秒ごとに「全期間・全スタッフ（いま133シート）」を取りに行く。打刻があるたびに一時保存（キャッシュ）が消え、作り直しに5〜6秒以上かかる。打刻の書き込みは「順番待ち10秒」を超えると失敗するが、no-corsのため誰も気づけない | `doGet getAll`・`doPost` のロック | 人が重なると待たされる・失敗する |
| E | 修正履歴が毎回「出勤 09:57→09:57:00」のような**書式違いだけで記録**される（EditLogの大半がこれ）。退勤時に**備考が二重になる**（「【本人修正済】 / 【本人修正済】」「4310 ９月分の交通費 / 4310 ９月分の交通費」）。退勤時、入力欄に既にある備考に、同じ備考をもう一度つなげているため | `logEditIfChanged`・`handlePunch` の備考処理 | 履歴が読めない、処理が遅くなる、Excelの備考が汚れる |

### 2.2 出力が1回で揃わない（依頼2-1）

11/7の調査どおり。出力ボタンは同期を呼ぶが、Excelは「押した瞬間に画面が持っていたデータ」で作る。同期が実行中・ローカル更新直後15秒は「成功」扱いでスキップされる。さらに同期結果を返す変数（`finalMerged`）はReactの更新処理の中で埋めているため、空のまま返ることがある。

### 2.3 「本人確認：未」（依頼2-2）

**ボタンは動いていて、記録もされている**（Confirmations シートに29件）。原因は保存の形:
- GASが対象月を `"2026-10"` という文字で書き込むと、スプレッドシートが**自動で日付（2026/10/01）に変換**してしまう。29行すべてが日付になっている。
- 読み出すときは「スタッフ名|2026-10」で探すが、実際は「スタッフ名|Thu Oct 01 2026 00:00:00 GMT+0900…」になっていて一致しない → 全員「未」。
- 同じ理由で「押し直したら上書き」も効かず、同じ月の行が増えている（小田さんなど）。

### 2.4 シートの見た目の違い（依頼2-3）

- 新しい人（東さん・杉坂さん・西尾さん）のシートは、テンプレート内の「マスタ」シートをコピーして作っている。マスタには**有給欄の罫線・セル結合・賄い列の書式などが無い**ため、草野さんのシートと見た目が違う（10月出力で確認: 西尾さんは有給欄の枠なし、残有休日数のセル結合なし、賄い「1」の位置ずれ、休憩0:00表示など）。
- テンプレート内の既存スタッフのシートもそれぞれ少しずつ違う（小出さん・山田さんなどは有給欄が無いのを後から書き足している、林さんだけ「オンライン業務」欄があり、有給欄と重なっている）。

### 2.5 有給の表示（依頼2-4）

- 有給管理簿は「設定」シートの**現在日＝今日（TODAY）**を基準に、残日数（N列）・次回付与日（I列）を計算している。アプリは出力した日にこの値を読むので、**出力日の値**になる。
- 例: 高橋さんは 11/1 に付与。10月分を11月に出力すると、残日数に11/1付与分が足され、次回発生も 2027.11.1 になる（10月末時点なら 2026.11.1 が正しい）。
- ほかに見つけた危険: ファイル探しが「名前に『年次有給休暇管理簿2026』を含む」なので、同じフォルダの「年次有給休暇管理簿**2026旧**」を拾う可能性がある。また管理簿の年度は5/1〜翌4/30なのに、アプリは対象月の「暦の年」でファイルを選ぶため、2027年1〜4月分で別の年度のファイルを読む。

## 3. 直し方

### 3.1 打刻を確実に保存する（原因A・B・C）

1. **打刻専用の保存命令 `punch` を新設（GAS）**。打刻ボタンからは「どの項目を何時に打ったか」だけを送る（例: 出勤=08:45）。サーバーは**その項目が空のときだけ書く**。既にある出勤を空や別の時刻で消さない。賄い・交通費・備考・休憩分数は「送られてきた値が空でなければ書く」。新旧判定で捨てない（遅れて届いた朝の出勤も、出勤欄が空なら入る）。
   - 履歴画面・管理者の修正は従来どおり `record`（1日分まるごと）で、本人が意図した修正として上書きする。削除も従来どおり。
2. **送信を「届いたか確認できる」形にする**。no-cors をやめ、GASの返事（`{status:'ok'}`）を読む（GASのWebアプリはこの形の送信に返事を返せる）。あわせて `keepalive: true` を付け、画面を閉じても送信を続けさせる。
   - 返事が ok → 未送信リストから消す。
   - 失敗・返事なし → 未送信リストに残し、打刻画面に「⚠ 未送信 n件（自動で再送します）」を出す。再送できたら消える。
   - 返事を読めない環境だった場合に備え、従来の「全件取得でクラウドに反映を確認したら消す」も残す（二重の安全）。
3. **再送を早める**。未送信分の再送を、全件取得と切り離して「アプリを開いたとき・画面に戻ったとき・20秒ごと」に行う。15秒保護の対象外にする（打刻が続く時間帯でも再送は止めない）。さらに打刻を受け付ける前に、その日のその人の最新行を GAS から1件だけ取り直す軽い問い合わせ（`getRecord`）を行い、相手の端末の打刻を反映してから「すでに出勤済み」等の判定をする（取れなければ今どおり手元のデータで続行）。再送は `punch` で送るので、クラウドの方が新しくても空欄は埋まる。
4. 「記録しました！」の表示は今のまますぐ出す（待ち時間を増やさない）。保存に失敗したときだけ未送信表示が残る。
5. **送信元の記録**: スプレッドシートの15列目に「送信元」（店舗PC／スマホの種類と、打刻・修正の別）を残す。次に漏れが起きたとき、どの端末で起きたか追えるようにする。アプリの表示・Excelには出さない。

### 3.2 待ち時間を減らす（原因D）

1. **全件取得を「直近2か月分」に絞る**。GASの `getAll` に `months=2` を渡すと、今月と先月のシートだけ読む（133シート→約30シート）。端末側は、取得範囲外の古いデータは手元のものを消さずに残す（今もクラウドに無いデータは残す作り）。
2. **自動同期の間隔を3秒→10秒**にし、画面が裏に回っている間は止める（戻ったら即同期）。打刻の15秒保護・8秒ルールなど既存の競合対策の値は変えない。
3. 修正履歴（EditLog）は、時刻を同じ書式（時:分）にそろえてから比べ、**本当に変わったときだけ**記録する。
4. 退勤時の**備考の二重化を止める**: 入力欄には既存の備考が入っているので、つなげずに入力欄の内容で置き換える。【本人修正済】は1回だけ付く。
   - 既に二重になっている備考はExcel出力時に重複部分を1つにまとめて出す（スプレッドシートの元データは書き換えない）。

### 3.3 エクセル出力（依頼2-1〜2-3）

1. **出力は対象月をクラウドから直接取って作る**。出力ボタンで GAS から対象月（と有給）を取得し、**取得したデータそのもの**でExcelを作る。手元の古いデータは使わない。同期の「スキップ」や15秒保護の影響を受けない専用の取得にする。取得に失敗したら「最新データを取れませんでした」と出して出力しない（今の「古いままで出しますか？」は廃止）。
   - 出力する端末に未送信の打刻がある場合は、先に送ってから取得する。
2. **本人確認**:
   - GAS: 対象月・確認日時をセルの書式「文字」で保存する（自動で日付にならない）。読むときは、既に日付になっている行も「2026-10」の形に直して照合する。同じ人・同じ月が複数あれば最後の日時を使う。既存29行は読み取り時の変換で正しく拾えるので、シートの手直しは不要。
   - 押し直したときは同じ行を上書きする（行が増えない）。
3. **レイアウト統一**: 全スタッフのシートを「草野久美子」シートを**型として丸ごと複製**して作る（列幅・行の高さ・罫線・セル結合・書式・印刷設定・土日の色まで同じ）。テンプレートにある各スタッフのシートは使わない。シート名だけ各スタッフの名前にする。
   - これで草野さん・高橋さん・西尾さんを含め全員が同じ形になる。
   - **林さんの「オンライン業務」欄はなくなる**（有給欄と重なっていたため）。10月は備考に「オンライン作業18140円」と書かれていたので、備考で足りると判断した。必要なら別途相談。
   - 出勤記録の無いスタッフのシートは今どおり出さない。外注用の出力は今回触らない。

### 3.4 有給を「対象月の末日時点」で出す（依頼2-4）

**方法（推奨）: 出力時に管理簿の一時コピーで「現在日」を月末にして計算させる**
1. 出力時、GASが有給管理簿を**一時的にコピー**する（原本は開いて読むだけで、一切書き込まない）。
2. コピーの「設定」シートの「現在日」（C5）を**対象月の末日**（10月分なら 2026/10/31）に書き換え、計算させてから、管理簿シートの残日数（N列）・次回付与日（I列）を読む。
3. 読んだらコピーはすぐゴミ箱へ移す。
4. 管理簿の計算式をそのまま使うので、オーナーが後から入れた10月の取得日も反映され、11/1付与分は入らない。
- 管理簿ファイルの選び方を直す: フォルダ内の「年次有給休暇管理簿」で始まり「旧」を含まないファイルのうち、「設定」の期首〜期末に対象月末が入るものを使う。見つからない・複数ある場合は出力時に知らせる（有給欄は空欄で出力は続ける）。
- 必要な権限の変更: コピーとゴミ箱移動のため、GASのドライブ権限を「読み取りのみ」→「ドライブの読み書き」に広げる。**初回だけ承認画面での再承認が必要**（GASの持ち主アカウントで）。

他の方法（不採用）:
- 毎月末に自動で値を控えておく: 月が明けてから入力された取得日が反映されないので不採用。
- アプリ側で付与日数の法定表まで計算し直す: 管理簿と二重管理になり食い違う恐れがあるので不採用。

## 4. 変えないこと

- スプレッドシートの構成（スタッフ名_年月 のシート、列1〜14の意味）。15列目を足すだけ。
- 打刻画面の操作、健康チェック・休憩の確認、有給申請、外注の出力、設定（名簿・PIN）の同期。
- 15秒・8秒の競合保護の値。
- 有給管理簿の原本（読むだけ）。

## 5. 反映の手順

1. **GAS を先に**更新する（新しい `punch`・`getAll months`・本人確認の読み書き・有給の月末計算・EditLog）。古いアプリからの `record` もそのまま受けるので、先に出しても今のアプリは動く。
   - スクリプトエディタに `gas_backup.gs` を貼り付け → `appsscript.json` の権限を変更 → 「デプロイを管理」で**今のデプロイを編集して新バージョン**にする（URLを変えない）→ 再承認。
2. 次に `timecard.html` を GitHub の main に入れる（Vercelが自動で公開）。
3. 各端末は再読み込みで新しい版になる。

## 6. 確かめ方

- **手元の試験**: GAS をまねた試験用サーバーをつくり、ブラウザ（Playwright）で次を確認する。
  - 出勤を送った直後に通信を切る → 未送信表示 → 通信を戻すと再送され表示が消える。
  - 端末Aで出勤、端末Bが出勤を知らないまま退勤 → 出勤が消えない。
  - 翌日に古い出勤が届く → 出勤欄が空なら入る、既にあれば変わらない。
  - 退勤で備考が二重にならない。
  - 出力ボタン1回で、試験データの月末分まで全員揃う。手元が古くても揃う。
  - 本人確認が「本人確認済み: 日時」で出る（日付に化けた行も拾える）。
  - 出力したExcelの全シートが草野さんのシートと同じ形（罫線・結合・書式・列幅・行の高さ）になっているかを自動で比較する。
- **GAS 側**: 本番の前に、テスト用のスタッフ「テスト」で 打刻→修正→削除→本人確認→出力 を1回行い、終わったら「テスト_202611」シートを消す（chihiro確認のうえ）。有給は10月分で出力し、11/1付与の高橋さんが「11/1付与分を含まない残日数」「次回発生 2026.11.1」になることを、管理簿の現在日を一時的に 10/31 にした値と照らす（照合は一時コピーで行い、原本は触らない）。

## 7. 危険と戻し方

- GASの返事を読む送信が、一部のスマホで動かない可能性 → その場合も未送信リスト＋全件取得での確認が残るので、今より悪くはならない。
- 一時コピーの作成に数秒かかる → 出力時のみ。今も有給取得と同期を並行しているので体感は大きく変えない。
- 戻し方: アプリは git で前のコミットに戻して push。GASは「デプロイを管理」で前のバージョンを選ぶ。15列目は残っても害はない。
