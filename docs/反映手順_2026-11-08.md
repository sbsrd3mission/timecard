# 反映手順（2026-11-08 打刻漏れとエクセル出力の修正）

この手順書は、エンジニアでない方が1人で反映できるように書いています。
**閉店後**、店舗PCとタブレットを使っていない時間に行ってください。全体で30〜40分ほどかかります。

大事な順番は1つだけです: **アプリ（timecard.html）を先に、GAS（gas_backup.gs）を後に** 更新します。
（逆にすると、古いアプリが新しい GAS に送れず、未送信がたまります。この順番なら、端末の中の未送信は消えません）

---

## 0. 前もって1回だけやること（反映の日より前でも可）

### 0-1. 有給の計算用スプレッドシートを作る
Excel の有給欄を「その月の末日時点」で出すために、計算専用のスプレッドシートを1つ作ります。

1. Google ドライブで、新しいスプレッドシートを作ります。
2. 名前を **「有給月末計算用（触らない）」** にします（1文字でも違うと動きません。かっこは全角です）。
3. 中身は何も入れません。この後もこのファイルは開いたり書き換えたりしないでください（GAS が自動で中のシートを入れ替えます）。
4. ブラウザの上のアドレス欄を見ます。`https://docs.google.com/spreadsheets/d/` の後ろから、次の `/` の前までが **ID** です。メモしておきます。
   - 例: `https://docs.google.com/spreadsheets/d/1AbC...xyz/edit` なら `1AbC...xyz`

### 0-2. 本番ファイルの ID を控える
次の2つの ID も同じやり方で控えます（GAS の「試験のときに本番を書き換えない仕組み」に使います）。
- 本番の勤怠のスプレッドシート（タイムカードバックアップ）の ID
- 有給管理簿（年次有給休暇管理簿20xx）の原本の ID（年度ごとにあればすべて）

## 1. 本番のスプレッドシートを丸ごと控える
1. 本番の勤怠のスプレッドシートを開きます。
2. 「ファイル」→「コピーを作成」で、名前を「タイムカードバックアップ_控え_2026-11-08」にしてコピーします。
3. コピーの ID もメモしておきます（戻すときの比べ合わせに使います）。

## 2. 店舗PC・タブレットの両方で、タイムカードのタブを閉じる
- ブラウザのタブ（タイムカードの画面）を閉じます。ブラウザごと閉じても構いません。
- 端末の中の未送信は消えません（閉じても残ります）。
- 古い版の自動同期は、このタブの中で動いています。閉じれば止まります。

## 3. アプリ（timecard.html）を公開する
1. `impl/punch-sync-and-export` の変更を main に取り込み、GitHub に送ります（ここはエンジニア担当が行います）。
2. Vercel の画面で、公開（デプロイ）が「Ready」になるまで待ちます。

## 4. 2台でタイムカードを開き、版を確かめる
1. 店舗PC・タブレットでタイムカードを開きます。
2. **まず画面のいちばん下の「版」の表示が `2026-11-08 v3` になっていることを確かめます。**
   - 違う版のままなら、管理者メニューの「🔄 最新版に強制再読み込み」を押すか、ブラウザの再読み込みをしてください。
3. 新しい版は、開いた瞬間に（通信より先に）古い未送信と手元の記録を端末の中に控え、新しい形式に変えます。
4. この時点では GAS がまだ古いので、未送信があれば「⚠ 未送信 n件」と出たままになります。**これで正常です。**
   - 打刻はこの間もできます（未送信として残り、手順5の後に自動で送られます）。

## 5. GAS を更新する（新バージョン）
1. 本番の勤怠のスプレッドシートを開き、「拡張機能」→「Apps Script」を開きます。
2. 今のコードをすべて選んで、リポジトリの `gas_backup.gs` の中身に置き換えます。
3. コードの上の方にある次の2行に、0-2 で控えた ID を `'...'` で囲んで書き込みます（複数あれば `,` で区切ります）。
   ```
   const PROD_TIMECARD_SS_IDS = ['本番の勤怠スプレッドシートのID'];
   const PROD_LEAVE_BOOK_IDS = ['有給管理簿の原本のID', '…'];
   ```
4. 💾（保存）を押します。
5. 左の「⚙ プロジェクトの設定」→ いちばん下の「スクリプト プロパティ」→「スクリプト プロパティを追加」で、次を登録して保存します。
   | プロパティ | 値 |
   |---|---|
   | `LEAVE_CALC_SS_ID` | 0-1 で控えた「有給月末計算用（触らない）」の ID |
   | `BACKUP_SS_ID` | 手順1で作った控えの ID（戻すときの比べ合わせ用） |
   - `MODE` というプロパティは**本番では登録しません**（あれば消します）。
6. 右上の「デプロイ」→「デプロイを管理」→ 今使っているデプロイの ✏（編集）→「バージョン」を **「新バージョン」** にして「デプロイ」。
   - **「新しいデプロイ」は押さないでください**（URL が変わってしまいます）。URL が今までと同じであることを確かめます。
7. 2台の画面を見ます。20秒ほどで「⚠ 未送信 n件」が消えれば、未送信が届いています。

### 5の後: 毎晩の自動の掃除（OpLog）を1回だけ設定する
1. Apps Script の上の関数の選び欄で `installOpLogPruneTrigger` を選んで「実行」を押します（初回は Google の許可の画面が出るので「許可」）。
2. 続けて `checkOpLogPruneTrigger` を選んで「実行」し、下の「実行ログ」に **「OK: OpLog の掃除（pruneOpLogDaily）は1つ設定されています」** と出ることを確かめます。
   - 「NG」と出たら、もう一度 `installOpLogPruneTrigger` を実行してください。
   - これは毎晩3時ごろに、180日より古い月の「OpLog_年月」シートを丸ごと消す設定です。

## 6. 2台で確かめる（これで完了）
1. それぞれの端末で「管理者メニュー」を開き、**「この端末の名前」** に、店舗PCは「店舗PC」、タブレットは「タブレット」と入れて「保存」を押します（1回だけ。エクセル出力の前に、2台の未送信を確かめるのに使います）。
2. 画面の下の表示が **「未送信 0件・時計のずれなし」** になっていることを確かめます。
   - 「時計のずれあり」と出たら、その端末の日付と時刻の設定を「自動」にしてください。
3. 管理者メニューに「⚠ 当てられなかった未送信 n件」の一覧が出ていたら、中身を見て、必要なものは履歴・修正画面から入れ直します。入れ直しが終わったら「入れ直しが終わったので一覧を消す」を押します。
4. 試しに、タブレットで1人「出勤」→ 店舗PCで同じ人を選んで「退勤」できることを確かめ、履歴画面で両方が残っていることを見ます（試しの記録は後で消すか、管理者メニューから直してください）。
5. 管理者メニューから先月分のエクセルを出力し、全員分そろっていること・有給欄に「有給は 年/月/日 時点」と出ていることを確かめます。

## うまくいかないとき・前の版に戻すとき

### 戻す前に（必ず）
1. **2台とも**、管理者メニューの「未送信を書き出す」を押して、出てきたファイルを保存します（送れない故障のときでも、未送信を残せます）。
2. できれば2台で「未送信 0件」になってから戻します。

### 戻す手順
1. アプリ: GitHub の main を、この反映の前のコミットに戻して公開します（エンジニア担当）。
2. GAS: 「デプロイを管理」→ ✏ →「バージョン」で前のバージョンを選んで「デプロイ」。
3. 2台を再読み込みします。
   - 古い版は新しい形式の未送信（端末の中の `timecard_op_queue`）を読みません。読めないだけで害はありません。書き出したファイルの一覧を見て、管理者が修正画面で入れ直してください。
4. データを控え（手順1のコピー）に丸ごと戻すことはしません（反映後の正しい打刻が消えるため）。
   Apps Script で `listRowsChangedSinceBackup` を実行すると、控えと今で「どれかの項目が変わった行」が実行ログに一覧で出ます。EditLog・OpLog と照らして、必要な行だけ直してください。

### もう一度新しい版にするとき
- 戻した後にもう一度新しい版にする場合も、この手順書の2〜6を同じ順番で行います。
- 古い版で書かれた行は、新しい版が自動で見分けて扱います（何もしなくて大丈夫です）。

## （参考）試験用に GAS を動かすとき
本番ではなく、控えのコピーで試験するときの決まりです（本番は書き換えません）。
1. 試験用の勤怠スプレッドシート（控えのコピー）の Apps Script に `gas_backup.gs` を貼り、「新しいデプロイ」で試験用の URL を作ります。
2. スクリプト プロパティに次を登録します。
   | プロパティ | 値 |
   |---|---|
   | `MODE` | `test` |
   | `TEST_ALLOWED_FILE_IDS` | 使ってよいファイルの ID を `,` 区切りで（試験用の勤怠ファイル・試験用の管理簿の写し・試験用の計算ファイル） |
   | `TEST_LEAVE_FOLDER_ID` | 試験用の管理簿の写しを入れたフォルダの ID |
   | `LEAVE_CALC_SS_ID` | 試験用の「有給月末計算用（触らない）」の ID |
3. 試験モードでは、登録していないファイルや本番のファイル（コードの `PROD_...` に書いた ID）は開かずに止まります。
   `PROD_TIMECARD_SS_IDS` に本番の ID を書いてあれば、本番以外のファイルで動いている GAS は `MODE` が無くても自動で試験扱いになります。
4. 試験用のアプリは、`timecard.html` の `GAS_URL` を試験用の URL に書き換えた**別のファイル**で開きます（本番の公開ファイルは書き換えません）。
