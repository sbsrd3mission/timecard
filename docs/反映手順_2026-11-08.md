# 反映手順（2026-11-08 打刻漏れとエクセル出力の修正）

この手順書は、エンジニアでない方が1人で反映できるように書いています。
**閉店後**、店舗PCとタブレットを使っていない時間に行ってください。手順1〜6は全体で30〜40分ほどかかります。

大事な決まりは2つです。
1. **本番に出す前に、手順0-2の「試験」で「全体: 合格」が出ていること**。合格していなければ、手順1以降に進みません。
2. **アプリ（timecard.html）を先に、GAS（gas_backup.gs）を後に** 更新します。
   （逆にすると、古いアプリが新しい GAS に送れず、未送信がたまります。この順番なら、端末の中の未送信は消えません）

コードの中身を書き換える作業はありません（ID などはすべて「スクリプト プロパティ」に入れます）。

---

## 0. 前もってやること（反映の日より前に）

### 0-1. Google の「確認されていないアプリ」の画面が出たとき（この手順書で何度か出ます）
Apps Script で初めて関数を「実行」したときや、新しい権限が必要になったときに、Google の確認画面が出ます。自分で作ったスクリプトなので、次の順に進めて大丈夫です。

1. 「承認が必要です」と出たら **「権限を確認」** を押します。
2. アカウントを選ぶ画面で、**このスプレッドシートの持ち主のアカウント**を選びます。
3. 「Google はこのアプリを確認していません」と出たら、左下の小さな **「詳細」**（または「詳細を表示」）を押します。
4. 下に出てくる **「（プロジェクト名）（安全ではないページ）に移動」** を押します。
5. 「（プロジェクト名）が Google アカウントへのアクセスをリクエストしています」の画面で、いちばん下までスクロールして **「許可」** を押します。
   - 項目ごとにチェックを入れる画面のときは、**すべてにチェック**を入れてから「続行」を押します。
6. 元の画面に戻り、関数がそのまま動きます。下の「実行ログ」を見てください。

### 0-2. 【必ず】本番に出す前の試験（コピーで行う。本番は書き換えません）
ここで「全体: 合格」が出なければ、本番には進まず、エンジニア担当に連絡してください。

1. 「タイムカード_試験用」（タイムカードバックアップのコピー。作成済み）を開き、（**名前に「試験」が入っていること**を確かめてから。入っていないファイルでは、守りのため試験が止まります）「拡張機能」→「Apps Script」を開きます。
2. 今のコードをすべて選んで、リポジトリの `gas_backup.gs` の中身に置き換え、💾（保存）を押します。
3. 左の「⚙ プロジェクトの設定」→ いちばん下の「スクリプト プロパティ」→「スクリプト プロパティを編集」で、`MODE` = `test` を1つ追加して保存します（ほかに登録するものはありません）。
4. 上の関数の選び欄で `runReleaseCheck` を選んで「実行」を押します（確認画面が出たら 0-1 のとおりに許可します）。
5. 下の「実行ログ」の**最後の行が「全体: 合格」**であることを確かめます。「不合格」が1つでもあれば、ここで止めて、実行ログをそのままエンジニア担当に送ってください。
6. 右上の「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」、実行するユーザー「自分」、アクセスできるユーザーは本番と同じにして「デプロイ」します。出てきた URL（試験用 URL）をエンジニア担当に渡します。**本番の URL とは違うこと**を確かめます。
7. エンジニア担当が、試験用 URL につないだ試験用のアプリ（本番とは別のファイル）を用意します。2台でそれを開き、出勤・退勤を押して、管理者メニューからエクセルを出力できることを確かめます（記録は「タイムカード_試験用」に入り、本番には入りません）。

ここまでできたら、手順1に進みます。

## 1. 本番のスプレッドシートを丸ごと控える
1. 本番の勤怠のスプレッドシートを開きます。
2. 「ファイル」→「コピーを作成」で、名前を「タイムカードバックアップ_控え_2026-11-08」にしてコピーします。
3. コピーの ID もメモしておきます（戻すときの比べ合わせに使います）。

## 2. 店舗PC・タブレットの両方で、タイムカードのタブを閉じる
- ブラウザのタブ（タイムカードの画面）を閉じます。ブラウザごと閉じても構いません。
- 端末の中の未送信は消えません（閉じても残ります）。
- 古い版の自動同期は、このタブの中で動いています。閉じれば止まります。

## 3. アプリ（timecard.html）を公開する
1. `impl/punch-sync-and-export` の変更を main に取り込み、GitHub に送ります（ここはエンジニア担当が行います）。
2. Vercel の画面で、公開（デプロイ）が「Ready」になるまで待ちます。

## 4. 2台でタイムカードを開き、版を確かめる
1. 店舗PC・タブレットでタイムカードを開きます。
2. **まず画面のいちばん下の「版」の表示が `2026-11-08 v3` になっていることを確かめます。**
   - 違う版のままなら、管理者メニューの「🔄 最新版に強制再読み込み」を押すか、ブラウザの再読み込みをしてください。
3. 新しい版は、開いた瞬間に（通信より先に）古い未送信と手元の記録を端末の中に控え、新しい形式に変えます。
4. この時点では GAS がまだ古いので、未送信があれば「⚠ 未送信 n件」と出たままになります。**これで正常です。**
   - 打刻はこの間もできます（未送信として残り、手順5の後に自動で送られます）。

## 5. GAS を更新する（新バージョン）
1. 本番の勤怠のスプレッドシートを開き、「拡張機能」→「Apps Script」を開きます。
2. 今のコードをすべて選んで、リポジトリの `gas_backup.gs` の中身に置き換えます（コードの中は何も書き換えません）。
3. 💾（保存）を押します。
4. 上の関数の選び欄で `registerProductionIds` を選んで「実行」を押します（確認画面が出たら 0-1 のとおりに許可します）。
   - 実行ログに **「OK: 本番の勤怠ファイル「（本番のファイル名）」を登録しました」** と出ることを確かめます。
   - 「NG」と出たら、開いているのが本番のファイルか確かめてください。
   - これで「試験のときに本番を書き換えない仕組み」に使う本番の ID が、スクリプト プロパティ（`PROD_TIMECARD_SS_IDS`）に自動で入ります。
5. 左の「⚙ プロジェクトの設定」→ いちばん下の「スクリプト プロパティ」→「スクリプト プロパティを編集」で、次を追加して保存します（`PROD_TIMECARD_SS_IDS` は 4 で入ったもので、触りません）。
   | プロパティ | 値 |
   |---|---|
   | `BACKUP_SS_ID` | 手順1で作った控えの ID（戻すときの比べ合わせ用） |
   - `MODE` というプロパティは**本番では登録しません**（あれば消します）。
6. 右上の「デプロイ」→「デプロイを管理」→ 今使っているデプロイの ✏（編集）→「バージョン」を **「新バージョン」** にして「デプロイ」。
   - **「新しいデプロイ」は押さないでください**（URL が変わってしまいます）。URL が今までと同じであることを確かめます。
   - 新しい権限が必要なときは確認画面が出ます。0-1 のとおりに許可します。
7. 2台の画面を見ます。20秒ほどで「⚠ 未送信 n件」が消えれば、未送信が届いています。

### 5の後: 毎晩の自動の掃除（OpLog）を1回だけ設定する
1. Apps Script の上の関数の選び欄で `installOpLogPruneTrigger` を選んで「実行」を押します（確認画面が出たら 0-1 のとおりに許可します）。
2. 続けて `checkOpLogPruneTrigger` を選んで「実行」し、下の「実行ログ」に **「OK: OpLog の掃除（pruneOpLogDaily）は1つ設定されています」** と出ることを確かめます。
   - 「NG」と出たら、もう一度 `installOpLogPruneTrigger` を実行してください。
   - これは毎晩3時ごろに、180日より古い月の「OpLog_年月」シートを丸ごと消す設定です。

## 6. 2台で確かめる（これで完了）
1. それぞれの端末で「管理者メニュー」を開き、**「この端末の名前」** に、店舗PCは「店舗PC」、タブレットは「タブレット」と入れて「保存」を押します（1回だけ。エクセル出力の前に、2台の未送信を確かめるのに使います）。
2. 管理者メニューの **「知っている端末を見る」** を押し、「店舗PC」「タブレット」が出ていることを確かめます。
   - 「名前なし（ID …）」の端末が出ていたら、それがもう使っていない端末（ブラウザの履歴を消す前の端末など）なら「一覧から消す」を押します。使っている端末なら、その端末で名前を付けてください。
   - 一覧に残っている端末は、エクセル出力の前に毎回「未送信0件・10分以内の知らせ」が確かめられます。確かめられない端末があると、出力の前に注意が出ます。
3. 画面の下の表示が **「未送信 0件・時計のずれなし」** になっていることを確かめます。
   - 「時計のずれあり」と出たら、その端末の日付と時刻の設定を「自動」にしてください。
4. 管理者メニューに「⚠ 当てられなかった未送信 n件」の一覧が出ていたら、「内容:」の行を見て、必要なものは履歴・修正画面から入れ直します。入れ直しが終わったら「入れ直しが終わったので一覧を消す」を押します。
5. 試しに、タブレットで1人「出勤」→ 店舗PCで同じ人を選んで「退勤」できることを確かめ、履歴画面で両方が残っていることを見ます（試しの記録は後で消すか、管理者メニューから直してください）。
6. 管理者メニューから先月分のエクセルを出力し、全員分そろっていること・有給欄の下に「有給は 年/月/日（出力日）時点」と出ていることを確かめます（有給の残日数・次回発生は、今までどおり出力した日の管理簿の値です）。
   - 「本人確認（確認済みの印）を取得できませんでした」などで止まったときは、少し待ってもう一度押します。続くときはエンジニア担当に連絡します。

## うまくいかないとき・前の版に戻すとき

### 戻す前に（必ず）
1. **2台とも**、管理者メニューの「未送信を書き出す」を押して、出てきたファイルを保存します（送れない故障のときでも、未送信と「当てられなかった未送信」の中身を残せます）。
2. できれば2台で「未送信 0件」になってから戻します。

### 戻す手順
1. アプリ: GitHub の main を、この反映の前のコミットに戻して公開します（エンジニア担当）。
2. GAS: 「デプロイを管理」→ ✏ →「バージョン」で前のバージョンを選んで「デプロイ」。
3. 2台を再読み込みします。
   - 古い版は新しい形式の未送信（端末の中の `timecard_op_queue`）を読みません。読めないだけで害はありません。書き出したファイルの一覧を見て、管理者が修正画面で入れ直してください。
4. データを控え（手順1のコピー）に丸ごと戻すことはしません（反映後の正しい打刻が消えるため）。
   Apps Script で `listRowsChangedSinceBackup` を実行すると、控えと今で「どれかの項目が変わった行」と「控えに無く、今だけにある行・シート（反映後に増えた記録）」が実行ログに一覧で出ます。EditLog・OpLog と照らして、必要な行だけ直してください。

### もう一度新しい版にするとき
- 戻した後にもう一度新しい版にする場合も、この手順書の2〜6を同じ順番で行います（`registerProductionIds` は登録済みなら、もう一度実行しても同じ値が入るだけです）。
- 古い版で書かれた行は、新しい版が自動で見分けて扱います（何もしなくて大丈夫です）。

## （参考）試験モードの決まり
- 試験モード（`MODE` = `test`、または本番の ID が登録されていて、本番以外のファイルで GAS が動いているとき）では、本番の勤怠ファイル（`PROD_TIMECARD_SS_IDS`）は開かずに止まります。GAS が入っている試験用のファイルは、名前に「試験」が入っているときだけそのまま使えます（本番に誤って MODE=test を入れても書き込まずに止まります）。
- それ以外のファイル（戻すときの控えなど）を試験で開くときは、スクリプト プロパティ `TEST_ALLOWED_FILE_IDS` にその ID を `,` 区切りで書きます（0-2 の試験では不要です）。
- 有給管理簿は、試験でも本番でも今までどおり読むだけです（書き換えません）。
- 試験用のアプリは、`timecard.html` の `GAS_URL` を試験用の URL に書き換えた**別のファイル**で開きます（本番の公開ファイルは書き換えません）。
