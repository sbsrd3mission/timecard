## 2. 調べてわかったこと

### 2.1 打刻の反映漏れ（依頼1）

**数字で見た現状**: 10月の勤怠181件のうち49件（27%）に【本人修正済】が付いている。修正履歴（EditLog）を見ると、9件は「退勤のときに出勤も同じ時刻で押され、あとで出勤時刻を直している」形（例: 東さん 10/3 出勤19:20・退勤19:20 → 出勤10:54 に修正。東さんは10月に5回）。つまり**朝の出勤がスプレッドシートに一度も届いていない**。また10/2には高橋さん10/1分の出勤09:40が空欄で上書きされて消えている記録がある。

打刻は基本的に**店舗のPCとタブレット（共用端末）**で行っている（chihiro 2026-11-08）。共用端末が2台あり、出勤と退勤を別の端末で押すことがあるため、「片方の端末が相手の打刻をまだ知らない」状態が起きやすい。さらに共用端末では次の事情が重なる。
- 打刻のたびに「ローカル更新後15秒は同期しない」保護が掛かり直す。出勤が続く時間帯はその端末の同期と再送が止まり続ける（再送は同期の中でしか動かないため）。
- タブレットは画面が消える・スリープすると、送信や再送が止まる。

原因は次の5つ（Aの「スマホを閉じる」は、共用端末では「タブレットのスリープ・送信中の通信切れ」に読み替え）。

| # | 原因 | どこ | 起きること |
|---|---|---|---|
| A | **送信の取りこぼし**。打刻は「送りっぱなし（no-cors）」で、届いたかを確認できない。さらに送信直後にスマホの画面を閉じたり別アプリに切り替えると、送信そのものが止まることがある（keepalive 指定なし）。それでも画面には「記録しました！」と出る | `sendToGAS` | 本人は押したつもり、クラウドには無い |
| B | **再送が遅く、しかも捨てられる**。未送信分の再送は「その端末で次にアプリを開いて、全件取得に成功したとき」だけ。次に開くのが翌日だと、その間に別端末で退勤が押されて新しい時刻の行ができており、サーバーは「古いデータ」として再送分を捨てる。端末側も「クラウドの方が新しい」と見て未送信リストから消す | `retrySendPending`・`writeRecord` の新旧判定 | 朝の出勤が永久に消える |
| C | **1日分の行をまるごと上書き**。打刻のたびに1日分の全項目（出勤・退勤・賄い・備考…）を送り、サーバーはそのまま行を書き換える。退勤を押した端末が出勤をまだ受け取っていないと、「出勤＝空」で上書きする | `handlePunch`・`writeRecord` | 出勤時刻が消える（10/1高橋さんの例） |
| D | **サーバーの負荷**。開いている全端末が3秒ごとに「全期間・全スタッフ（いま133シート）」を取りに行く。打刻があるたびに一時保存（キャッシュ）が消え、作り直しに5〜6秒以上かかる。打刻の書き込みは「順番待ち10秒」を超えると失敗するが、no-corsのため誰も気づけない | `doGet getAll`・`doPost` のロック | 人が重なると待たされる・失敗する |
| E | 修正履歴が毎回「出勤 09:57→09:57:00」のような**書式違いだけで記録**される（EditLogの大半がこれ）。退勤時に**備考が二重になる**（「【本人修正済】 / 【本人修正済】」「4310 ９月分の交通費 / 4310 ９月分の交通費」）。退勤時、入力欄に既にある備考に、同じ備考をもう一度つなげているため | `logEditIfChanged`・`handlePunch` の備考処理 | 履歴が読めない、処理が遅くなる、Excelの備考が汚れる |

### 2.2 出力が1回で揃わない（依頼2-1）

11/7の調査どおり。出力ボタンは同期を呼ぶが、Excelは「押した瞬間に画面が持っていたデータ」で作る。同期が実行中・ローカル更新直後15秒は「成功」扱いでスキップされる。さらに同期結果を返す変数（`finalMerged`）はReactの更新処理の中で埋めているため、空のまま返ることがある。

### 2.3 「本人確認：未」（依頼2-2）

**ボタンは動いていて、記録もされている**（Confirmations シートに29件）。原因は保存の形:
- GASが対象月を `"2026-10"` という文字で書き込むと、スプレッドシートが**自動で日付（2026/10/01）に変換**してしまう。29行すべてが日付になっている。
- 読み出すときは「スタッフ名|2026-10」で探すが、実際は「スタッフ名|Thu Oct 01 2026 00:00:00 GMT+0900…」になっていて一致しない → 全員「未」。
- 同じ理由で「押し直したら上書き」も効かず、同じ月の行が増えている（小田さんなど）。

### 2.4 シートの見た目の違い（依頼2-3）

- 新しい人（東さん・杉坂さん・西尾さん）のシートは、テンプレート内の「マスタ」シートをコピーして作っている。マスタには**有給欄の罫線・セル結合・賄い列の書式などが無い**ため、草野さんのシートと見た目が違う（10月出力で確認: 西尾さんは有給欄の枠なし、残有休日数のセル結合なし、賄い「1」の位置ずれ、休憩0:00表示など）。
- テンプレート内の既存スタッフのシートもそれぞれ少しずつ違う（小出さん・山田さんなどは有給欄が無いのを後から書き足している、林さんだけ「オンライン業務」欄があり、有給欄と重なっている）。

### 2.5 有給の表示（依頼2-4）

- 有給管理簿は「設定」シートの**現在日＝今日（TODAY）**を基準に、残日数（N列）・次回付与日（I列）を計算している。アプリは出力した日にこの値を読むので、**出力日の値**になる。
- 例: 高橋さんは 11/1 に付与。10月分を11月に出力すると、残日数に11/1付与分が足され、次回発生も 2027.11.1 になる（10月末時点なら 2026.11.1 が正しい）。
- ほかに見つけた危険: ファイル探しが「名前に『年次有給休暇管理簿2026』を含む」なので、同じフォルダの「年次有給休暇管理簿**2026旧**」を拾う可能性がある。また管理簿の年度は5/1〜翌4/30なのに、アプリは対象月の「暦の年」でファイルを選ぶため、2027年1〜4月分で別の年度のファイルを読む。

## 3. 直し方（改訂第2版: Argon・Codex の指摘を反映）

### 3.1 打刻を確実に保存する（原因A・B・C）

**(1) 送る単位を「1回の押下」にする**
- 打刻ボタンを押すたびに「操作」を1件つくる: `{opId（一意な番号）, staffName, date, kind（in/out/break_in/break_out/info）, time, attrs, at（押した時刻）, device}`。
  - `attrs` はその押下で確定した値をすべて明示して送る: 賄い（true/false）、交通費（数値 or なし）、休憩分数（退勤時は必ず数値。0 も 0 として送る）、備考（入力欄の内容そのもの）。「送っていない」と「空にした」を区別できるよう、送る項目は必ず値を入れ、送らない項目はキー自体を入れない。
- 未送信リストは**操作ごとに1件**で持つ（今の「1人1日1件」で上書きされる形をやめる。通信断の間に出勤→退勤と押しても両方残る）。
- 今の打刻処理は、送るデータをReactの更新処理の中で作っており、「記録しました」と出ても送られないことがある（timecard.html 2235〜2270行付近）。**送るデータは更新処理の外で先に作る**。
- 古い形式の未送信リスト（1日分まるごと）が端末に残っている場合は、起動時に一度だけ「時刻の入っている項目ごとの打刻操作」に変換して新しいリストへ移す（まるごと上書きでは送らない）。

**(2) サーバー（GAS）の新命令 `punch` の書き込みルール**
1. その日の行が「削除済み」または「有給」なら**何も書かない**（返事は `skipped`）。
2. 時刻（出勤・中抜け開始・中抜け終了・退勤）は、**その欄が空で、かつ「手修正時刻」より後に押された操作のときだけ**書く。既にある時刻は消さない・変えない。人が修正画面で消した時刻を、遅れて届いた古い打刻で復活させない。
3. 賄い・交通費・休憩分数・備考（attrs）は、「項目更新時刻」より新しい操作のときだけ、送られてきた値をそのまま書く（0・なし・空もそのまま）。古い操作は書かない。
4. 書いたら「項目更新時刻」を操作の時刻にする。送信元（店舗PC/タブレット等）を記録する。
5. 同じ opId が2回届いても結果は同じ（時刻は空欄のときだけ、attrs は時刻比較）なので二重書き込みにならない。

**(3) 修正画面・管理者の修正（`record`）**
- 新しいアプリは修正画面からの保存に `editSource:'edit'` を付ける。これは今どおり1日分を上書きし、「手修正時刻」を記録する（意図した削除・変更を守る）。
- `editSource` の無い `record`（**更新前の古いアプリ**が打刻で送ってくるもの）は、時刻欄について「既にある時刻を空で消さない」扱いにする（古い端末が残っていても出勤が消えない）。

**(4) スプレッドシートの列の追加**
- 15列目「送信元」、16列目「手修正時刻」、17列目「項目更新時刻」を足す。書き込み時に列が足りないシートは17列まで広げる（今は14列まで広げる処理しか無く、そのままだとエラーで全打刻が失敗するため）。読み込みも17列まで読む（列が無い古いシートは空として扱う）。

**(5) 届いたかの確認と再送**
- 送信は no-cors をやめ、GASの返事を読む（`keepalive: true` も付ける。1回の送信は64KB未満に収まるよう、再送は20件ずつに分ける）。
- 返事は**HTTPの成否ではなく中身で判定**する（GASは順番待ち10秒超えでも200で `status:'error'` を返すため）。返事に「処理した opId の一覧と結果（applied/skipped）」を入れ、載っていた操作だけ未送信リストから消す。
- 返事が読めない環境のための予備確認（全件取得での確認）も、**操作ごと**に行う: その項目に値が入っている（時刻）、または項目更新時刻がその操作以降（attrs）、または行が削除・有給、なら届いた（または不要になった）とみなして消す。「行の更新時刻が新しいか」だけでは消さない。
- 再送は全件取得と切り離し、「起動時・画面に戻ったとき・20秒ごと」。15秒保護の対象外。打刻画面に「⚠ 未送信 n件」を表示する（再送できたら消える）。
- 打刻を受け付ける前に、その人のその日の行だけを GAS から取り直す（`getRecord`、軽い問い合わせ）。もう一方の共用端末の打刻を反映してから「すでに出勤済み」等を判定する。取れなければ手元のデータで続行し、上の(2)のルールで安全に合流させる。
- 「記録しました！」はすぐ出す（待ち時間を増やさない）。

**(6) 本人確認ボタン**
- 押したらすぐ「確認済み」と表示しているが、送信失敗時に再送していない。打刻と同じ未送信リストに載せて、届くまで再送する。

### 3.2 待ち時間を減らす（原因D・E）

1. **全件取得を「直近2か月分」に絞る**: `getAll` に `months=2`。対象外の古い月は手元のデータを消さずに残す。
   - 古い月の履歴画面を開いたときは、その月だけを `month=YYYYMM` で取りに行く（削除の反映もこのとき行う）。出力も対象月を `month=` で取る。
   - サーバーの一時保存（キャッシュ）は**取得範囲ごとに別の名前**で持つ（2か月分・各月・全件）。書き込みがあったら、全部まとめて捨てる（名前の一覧を控えておき、一括で消す）。
   - 一部のシートが読めなかった場合、今は黙って成功を返している（gas_backup.gs 204〜209行）。読めなかったシート名を返事に入れ、アプリの出力はそれがあれば止める。
2. 自動同期の間隔を **3秒→10秒**、画面が裏のときは止める。15秒・8秒の保護の値は変えない。
3. EditLog は時刻を「時:分」にそろえて比べ、本当に変わったときだけ記録する。
4. 退勤時の備考の二重化を止める（入力欄の内容で置き換え）。既に二重のものは Excel 出力時に重複を1つにまとめる（元データは書き換えない）。

### 3.3 エクセル出力（依頼2-1〜2-3）

1. **出力は対象月をクラウドから直接取って作る**: 出力前に未送信リストを送り切る → `getAll month=対象月`、設定（名簿・本人確認）、有給 を取得 → **取得したデータそのもの**でExcelを作る。どれか取れない・読めないシートがある場合は理由を出して出力しない。
2. **本人確認**: GAS は対象月・確認日時の**セルを先に「書式なしテキスト」にしてから**書く（上書き時も同じ）。読むときは日付になっている既存行を **日本時間で** 「YYYY-MM」に直す（時差で1か月前にずれないように）。同じ人・同じ月が複数行あれば最後の日時を使う。押し直しは同じ行を上書きする。
3. **レイアウト統一（全員を草野さんの形に）**:
   - テンプレート（Excel）を作り直す: 「マスタ」シートを**草野久美子シートと完全に同じ形**（列幅・行の高さ・罫線・結合・書式・条件付き書式・印刷設定・数式）に置き換え、データ欄を空にしたものにする。この作り直しは手元（Python）で行い、作った後に草野さんのシートと自動比較して一致を確認する。
   - 出力時は、全スタッフのシートをこのマスタから複製して作る。ExcelJSには公式の「シート丸ごと複製」が無いため、マスタの中身（シートの設計図 `model`）を写して名前だけ変える方法をとり、**出力後のファイルを自動テストで検査する**（全シートの列幅・行の高さ・罫線・結合・書式・条件付き書式・印刷設定・数式がマスタと同じか）。合わない項目があれば、その項目は個別に写す処理を足す。テンプレート内の各スタッフ用シートは使わない。
   - **オンライン業務欄（chihiro指示 2026-11-08）**: 有給欄は全員同じ位置（A33〜E34）。その下に別枠「オンライン業務」を作る。対象月の備考に「オンライン」を含む日があるスタッフだけに出す（今は林さん。毎月ある）。
     - 位置: A36〜E41（マスタの C36:D36 の結合は外す）。A36「オンライン業務」、37〜40行に1件1行で C=日付（m/d）・D=備考の文言（【本人修正済】は除く）・E=金額、41行「合計」E41=SUM(E37:E40)。罫線は有給欄と同じ細線。
     - 金額は備考の「数字（カンマ可）＋円」を拾う（例: オンライン作業代21,565円 → 21565）。拾えないときは E を空欄にして文言だけ転記（推測で埋めない）。5件以上なら40行目に「ほか n件（備考参照）」。
     - 備考欄の元の記載は残す。林さんの過去6か月の記載はすべてこの方法で拾える。
   - 出勤記録の無いスタッフのシートは今どおり出さない。外注用の出力は今回触らない。

### 3.4 有給を「対象月の末日時点」で出す（依頼2-4、chihiro選択 2026-11-08）

管理簿の原本は今までどおり「今日」基準のまま（スタッフに今の残日数を答える用）。Excelに出す値だけ、月末時点で計算する。

**方法（改訂: ドライブ全体の書き込み権限は使わない）**
1. 出力時、GASが**作業用の新しいスプレッドシート**を作る（名前は `tmp_timecard_有給計算_削除可`。「年次有給休暇管理簿」で始まらない名前にして、ファイル探しに引っかからないようにする）。作成はスプレッドシート権限でできる。
2. 管理簿の「設定」「スタッフ名簿」「管理簿」の3シートを、この作業用に**シートごとコピー**（`copyTo`）し、元と同じ名前に付け直す。原本は開いて読むだけで書き込まない。
3. 作業用の「設定」C5（現在日）を対象月の末日にし、計算を確定させて（`flush`）、管理簿の残日数（N列）・次回付与日（I列）を読む。
4. **自己点検**: 同じ作業用で C5 を「今日」にした値が、原本の今の値と全員一致するかを先に確かめる。一致しなければ（コピーで計算式が壊れた等）月末値は使わず、出力時に「有給は出力日時点の値です」と注意を出して原本の値を使う。
5. 読み終わったら作業用ファイルをゴミ箱へ移す。失敗しても必ず消すよう「最後に必ず実行」の形にし、さらに毎回の実行前に、同じ名前の残骸があれば先に消す。
- 必要な権限: 今の「スプレッドシート」「ドライブ読み取り」に、**「このアプリが作ったファイルだけ」を扱える権限（drive.file）**を足す（作業用ファイルを消すため）。ドライブ全体の書き込み権限は使わない。初回だけ再承認が必要。
- 管理簿ファイルの選び方: フォルダ内で「年次有給休暇管理簿」で始まり「旧」を含まないファイルのうち、「設定」の期首〜期末に対象月末が入るもの。見つからない・複数ある場合は出力時に知らせる（有給欄は空欄で出力は続ける）。
- この方法が本当に動くか（コピー後に配列数式・LET を含む計算が新しい現在日で再計算されるか）は、実際のGASで実装前に試す。動かなければ、この節だけ「出力日時点＋基準日の注記」に切り替えて相談する。

## 4. 変えないこと

- スプレッドシートの構成（スタッフ名_年月 のシート、列1〜14の意味）。15〜17列目を足すだけ。
- 打刻画面の操作、健康チェック・休憩の確認、有給申請、外注の出力、設定（名簿・PIN）の同期。
- 15秒・8秒の競合保護の値。
- 有給管理簿の原本（読むだけ）。

## 7. 確かめ方

- **手元の自動テスト**（GASをまねた試験用サーバー＋Playwright）
  - 通信断で出勤→退勤と押す → 2件とも未送信リストに残り、復旧後に両方届く。
  - 端末Aで出勤、端末Bが知らないまま退勤 → 出勤が消えない。古いアプリ形式の `record`（出勤空）でも消えない。
  - 修正画面で出勤を消した後、古い出勤が遅れて届く → 復活しない。削除済み・有給の日にも書かれない。
  - 休憩0分・賄いなしを明示して送る → 0・なしのまま（45分に化けない）。
  - GASが `status:error`（順番待ち超え）を返す → 未送信のまま残り、再送される。
  - 出力ボタン1回で対象月が全員揃う（手元が古くても）。読めないシートがあれば出力しない。
  - 本人確認が「本人確認済み: 日時」で出る（日付に化けた既存行も拾える）。
  - 出力Excelの全シートがマスタ（＝草野さんの形）と同じ形か自動比較。オンライン業務欄の金額・合計。
- **実際のGASで**（本番の前に、控えのコピーにつないだテスト用デプロイで）: `punch`・`getAll months/month`・本人確認・有給の月末計算（自己点検込み）を確認。10月分で高橋さん（11/1付与）が付与前の残日数・次回 2026.11.1 になること。
- **店舗の実機で**（合格条件）: タブレットで出勤→PCで退勤して両方残る／タブレットのWi-Fiを切って打刻→「未送信1件」表示→Wi-Fiを戻して20秒以内に消える／2人続けて打刻しても待たされない／出力1回で揃う。

## 8. 危険と戻し方

- GASの返事を読む送信が一部の端末で動かない可能性 → 未送信リスト＋操作ごとの予備確認が残るので、今より悪くならない。
- 有給の月末計算が実GASで動かない可能性 → 3.4の最後のとおり切り替えて相談。
- 戻し方: アプリは git で前のコミットに戻して push。GASは「デプロイを管理」で前のバージョン。データは手順0の控えから戻す。
